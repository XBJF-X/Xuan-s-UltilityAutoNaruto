# productContext.md — 产品背景与用户体验

## 为什么做这个项目

《火影忍者》手游拥有大量重复性日常任务（每日、周常、活动、体力清理、好友互动等）。玩家每天需手动执行数十次固定操作，耗时且枯燥。本项目通过**场景识别 + 模拟点击**把这些重复操作自动化，让玩家"挂机"完成日常。

## 解决的问题

1. **重复劳动**：固定的点击序列、固定 UI 位置，交给脚本自动化。
2. **多账号管理**：多个玩家账号（配置）需独立保存账密与各自的任务开关/参数，互不干扰。
3. **调度与定时**：任务分每日/每周/活动，需按优先级与上次执行时间自动规划下一次执行。
4. **可观测性**：自动化执行需实时日志反馈，且多账号日志必须按配置隔离，否则无法排查哪个账号出问题。
5. **UI 变化适配**：游戏界面会更新（如"好友体力"UI 变化），需场景/元素识别与可配置任务参数来适配。

## 目标用户与使用场景

- 目标用户：火影忍者手游玩家、多开小号党。
- 使用场景：启动助手 → 勾选启用任务 → 配置任务参数 → 启动调度器 → 挂机；助手自动在合适时机执行各任务并记录日志。

## 用户体验目标（V2）

1. **三栏工作台**：左侧配置列表（切换账号）、中间任务树（按每日/每周/活动分组）、右侧内容区（总览/详情/日志），一次点击直达。
2. **实时日志可见**：启动调度器后日志即推送到界面，按 config_id 隔离；支持调试模式（显示 DEBUG）、保存截图开关、自动滚动；后台搁置/刷新/重连后日志不丢失。
3. **总览即状态**：Dashboard 展示当前配置所有任务的状态（执行中/就绪/等待）、优先级、下次执行时间，并可"立即执行"。
4. **配置操作便捷**：配置项支持右键重命名/删除，顶栏提供新建入口。
5. **全局工具**：检查更新（可视化弹窗 + 进度条）、反馈打包（替代原"打开日志目录"）、跳转 GitHub 与 Q&A。
6. **资源管理便捷**：ResourceManager 页面（`/resourcemanager`）在新前端完成场景/元素/边的完整增删查改（场景树、元素表格、边管理、元素迁移），初始化一次性全量读取（单请求返回全部场景+元素），旧 `tool/ResourceManager` 停用；另有独立页"场景资源图"（`/resource-graph`，Canvas 力导向图，双击节点进入）与"场景编辑器"（`/resource-scene/:sceneId`，场景底图 + 元素框 + 属性面板）。

## 关键交互路径

- 启动 → Layout.vue 三栏布局 → 选择/新建配置 → 中间任务树 → 点击任务进入 TaskConfigPanel 修改开关与参数 → 点击"启动"调度器 → Dashboard 观察任务状态 → LogPanel 查看实时日志。
- 顶栏"检查更新" → 打开 UpdateDialog.vue → `GET /api/utils/check-update` 对比 version.json 与 GitHub master SHA → 展示本地/云端版本对比 + 云端提交历史 + "最新/本地"徽标 → 用户确认后点"立即更新" → `POST /apply-update` 后台执行，弹窗内 `n-progress` 进度条显示下载/解压/替换/写版本记录各阶段 → `GET /update-status` 轮询。
- 顶栏"反馈"（原"打开日志目录"）→ 打开 FeedbackDialog.vue → `GET /api/utils/feedback/options` 按 `log/<用户名>/` 目录生成日期选项（MM-DD）→ 选日期后按需返回该日期 screenshot/ 下的任务选项（单任务默认选中、多任务可多选、无截图跳过）→ 选保存位置（`POST /browse-folder` 系统文件夹对话框）→ `POST /feedback/package` 后台打包 `XuanFeedBook_{用户名}_{YYYYMMDD}.zip` → 弹窗显示压缩进度条 → `GET /feedback/package-status` 轮询。
- 程序启动时自动检查更新（`checkUpdateOnStart`）：仅当云端最新提交与本地最新提交不一致（has_update）时才弹出更新窗口；网络异常静默忽略。
- 实时日志在后台搁置/刷新/WebSocket 重连后不丢失：LogPanel 挂载/configId 切换/重连成功时通过 `GET /log-history` + ws.ts `mergeHistory` 增量补齐历史日志。

## 与 V1 的体验差异

- V1：PySide6 单窗口桌面程序，日志在本地控件内，配置为本地文件。
- V2：Web 界面（Electron 壳），FastAPI 独立服务，WebSocket 实时推送、按 config_id 隔离的日志流；提供可视化更新弹窗与反馈打包功能。
